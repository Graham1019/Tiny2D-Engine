## 在主设备开始验收

在 Finder 中展开 ZIP 或使用下面的命令。先在候选 ZIP 所在目录校验 SHA256SUMS，再从新解压目录启动。继续保留两个 App 的相对位置。所有手动项目的当前状态为 **Pending User Acceptance**。签名保护的负向测试使用另一次临时解压。保留原 ZIP 与首次解压的验收目录。

```sh
OUT=$(mktemp -d)
PRODUCT="$OUT/Tiny2D-Showcase-0.6.0-rc1-macos-arm64"
APP="$PRODUCT/Tiny2D Showcase.app"
LAB="$APP/Contents/MacOS/tiny2d_lab"
EXAMPLES="$APP/Contents/Resources/assets/examples"
WORK=$(mktemp -d)
shasum -a 256 -c SHA256SUMS &&
ditto -x -k Tiny2D-Showcase-0.6.0-rc1-macos-arm64.zip "$OUT" &&
open "$APP"
```

以下命令从 ZIP 所在目录运行，每次创建独立临时副本。输出拒绝或签名检查行为与预期不符时，命令组会退出并保留现场。

```sh
(
  set -eu
  TMP_CHECK=$(mktemp -d)
  ditto -x -k Tiny2D-Showcase-0.6.0-rc1-macos-arm64.zip "$TMP_CHECK"
  PAIR="$TMP_CHECK/Tiny2D-Showcase-0.6.0-rc1-macos-arm64"
  SURV="$PAIR/Tiny2D Survivor.app"
  verify_pair() {
    codesign --verify --deep --strict "$SURV"
    codesign --verify --deep --strict "$PAIR/Tiny2D Showcase.app"
  }
  verify_pair
  for flag in capture trace metrics; do
    target="$SURV/Contents/Resources/test-$flag"
    if "$SURV/Contents/MacOS/Tiny2DSurvivor" --frames 2 "--$flag" "$target"; then exit 1; fi
    test ! -e "$target"
  done
  (cd "$TMP_CHECK" && "$SURV/Contents/MacOS/Tiny2DSurvivor" --frames 2 --capture "合法 外部.png")
  verify_pair
  open "$TMP_CHECK/合法 外部.png"
)
```

最后两条命令从源码仓库根目录执行，使用本轮新建的 Release 构建和前面定义的 WORK 目录。诊断基线的 Sequence 3 为 AdvanceTick，Epoch/Tick 1/39 → 1/40。当前有效状态在首次分歧处得到保护。在 Replay Inspector 中把只读的[错误 Hash 示例](../data/m112/bad-sequence-3.replay)填入 Replay path 并点 Load Replay，观察首次出错的 Sequence 和此前场景。[最终构建重新验证的拒绝记录](../data/m112/file-rejections.log)
